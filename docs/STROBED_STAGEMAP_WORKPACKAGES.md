## 1. Contract (proposed, fixed in WP1)

### Object dictionary

| Index | Name | Type | Node | Meaning |
|---|---|---|---|---|
| 0x2107 | `LASER_STROBE_ENABLE` | u8[4] | illumination | 1 = flash on every SYNC, PWM detached from the pin |
| 0x2108 | `LASER_STROBE_DELAY_US` | u32[4] | illumination | D, from SYNC reception to LED on |
| 0x2109 | `LASER_STROBE_WIDTH_US` | u32[4] | illumination | w, clamped to `STROBE_MAX_WIDTH_US` |
| 0x210A | `LASER_STROBE_COUNT` | u32[4], read-only | illumination | flashes fired since enable |
| 0x200C | `MOTOR_SYNC_POSITION` | i32[4], read-only | motor | step count latched at the last SYNC |
| 0x200D | `MOTOR_SYNC_COUNT` | u16[4], read-only | motor | SYNCs seen since latch enable |
| 0x200E | `MOTOR_SYNC_LATCH_ENABLE` | u8[4] | motor | 1 = latch on SYNC and send TPDO3 |

- **TPDO3 on motor nodes** (0x1802 / 0x1A02): COB-ID 0x380 + node (the stack's predefined
  TPDO3 base, so the node-id is added automatically), 6 bytes = 0x200C + 0x200D, event-driven,
  no inhibit, no event timer. Invalid by default in OD.c; motor slaves make it valid at boot
  (`SyncLatch::setupSlave`) and it only goes out after a SYNC while 0x200E = 1. The master
  reads it by COB-ID in `CAN_ctrl_task`. No new RPDO is needed on the master.
- **SYNC settings stay default on every node:** 0x1005 = 0x80, 0x1006 = 0, 0x1019 = 0. The
  master sends SYNC manually. A counter set on one node only makes the others reject SYNC.

### Serial JSON on the master

```jsonc
// strobe configuration, routed by DeviceRouter (REMOTE: SDO to node 30, LOCAL: LaserStrobe)
{"task":"/laser_act","LASERid":4,"strobe":{"enable":1,"delayUs":1200,"widthUs":20}}

// one constant-velocity line; axis 1 = X (Stepper enum A=0, X=1, Y=2, Z=3)
{"task":"/motor_act","strobesweep":{"axis":1,"target":250000,"speed":20000,
  "periodUs":33333,"trigUs":100,"laser":4,"report":16}}
{"task":"/motor_act","strobesweep":{"stopped":1}}

// reports every `report` frames (n = frame number, gaps show lost CAN frames), then completion
{"strobesweep":{"n":[33,34,35],"x":[12001,12400,12799]}}
{"strobesweep":true,"frames":480,"camera":480,"flashes":480,"positions":480,"latch":1,
 "strobe":1,"aborted":0,"success":1,"qid":17}

// capability: /modules_get lists "strobe":1 (laser strobe) and "strobesweep":1 (sweep).
// Older firmware lacks both keys; hosts then keep the free-running prescan.
// /laser_act strobe answer:
{"strobe":{"supported":1,"enabled":1,"remote":1,"node":30,"delayUs":1200,"widthUs":20,"count":0},"return":1,"qid":5}
```

### Safety limits (PinConfig, clamped on the node, not only in the host)

| Constant | Default | Where |
|---|---|---|
| `STROBE_MAX_WIDTH_US` | 1000 | illumination node |
| `STROBE_MAX_DUTY_PERMILLE` | 50 | illumination node; a flash that would exceed it is skipped and counted |
| `STROBE_TRIGGER_US` | 100 | master, camera trigger pulse width |

## 3. Work packages

### WP0 — Feasibility bench *(gate, no code)*

**Goal:** prove the hardware can do it before any firmware is written.

- **LED driver.** With today's firmware, set node 30 laser 0 to 1 kHz PWM (OD 0x2102) and
  2 % duty (0x2100). That yields isolated 20 µs pulses 1 ms apart. Watch the light with a
  photodiode on a scope.
- **HIK camera.** From the MVS feature tree, record the readout or line time at the planned
  ROI, whether global reset release exists, the maximum trigger rate and trigger caching.
  A temporary scope probe on the camera's exposure-active output is fine on the bench.
- **Acceptance:** light rise and fall ≤ 2 µs, pulse height ≥ 90 % of the DC level, no
  soft-start ramp. Decision recorded: go, change the LED driver, or accept a longer flash.

### WP1 — Object dictionary contract and bench tooling

**Depends:** WP0 go. **Goal:** freeze §1 in all repos and give the bench a SYNC source.

- **Automated:** the three `pio` builds pass. A second run of `regenerate_all.py` produces
  no diff. The uc2canopen test parses uc2-ESP's `uc2_indices.py` and fails on any mismatch
  with `od.py`. `send_sync()` emits exactly one standard frame 0x080 with no data.
- **Bench:** SDO reads of every new entry return their defaults on flashed nodes. `candump`
  shows TPDO1 traffic unchanged.

### WP2 — SYNC hook in the CAN task *(all nodes)*

**Depends:** WP1. **Goal:** a microsecond-class callback on SYNC reception.

- **Automated:** native test of the filter. A standard frame 0x080 with DLC 0 is accepted.
  DLC ≠ 0, extended IDs and RTR frames are rejected. Registered callbacks run in order.
- **Bench:** a debug build toggles a spare GPIO in the hook. `send_sync()` at 50 Hz for
  10 000 frames, with the LED ring animating and SDO traffic running. Scope the end of the
  SYNC frame on CAN_H against the GPIO edge.
- **Acceptance:** p99 latency ≤ 100 µs. The CANopen stack still processes SYNC normally.

### WP3 — Strobe engine on the illumination node

**Depends:** WP2. **Goal:** exact flashes on GPIO4 from the SYNC timestamp.

- **Automated:** native tests of `StrobeTiming.h`: width clamp, duty limiter skips and
  counts, disabling restores the previous PWM value, config changes while armed apply to
  the next SYNC only.
- **Bench:** GPIO4 width 20 ± 1 µs and delay D ± 5 µs against the hook timestamp. A 1 kHz
  SYNC flood respects the duty cap. `/laser_act` values are refused while strobing.
  Disabling restores the previous brightness.
- **Acceptance:** also, the LED stays off after node reset, bus-off and firmware crash.

### WP4 — Position latch on the motor node

**Depends:** WP2. Runs in parallel with WP3. **Goal:** a position for every SYNC.

- **Automated:** native test of the TPDO3 payload packing.
- **Bench:** stage at constant speed, `send_sync()` at 50 Hz, TPDO3 recorded with
  `candump`. Latched positions against SYNC time fit a line.
- **Acceptance:** fit residual RMS ≤ the steps travelled in 50 µs. TPDO1 and `isDone`
  behaviour are unchanged. With the latch disabled, TPDO3 stays silent.

### WP5 — Sweep orchestration on the master

**Depends:** WP3, WP4. **Goal:** one serial command runs a strobed line end to end.

- **Automated:** native tests: parameter validation (period ≥ trigger pulse plus margin,
  speed > 0, laser routed), report batching and JSON shape, the abort state machine.
- **Bench:** scope HAT GPIO27 against node 30 GPIO4 over 10 000 frames, with Bluetooth on
  and off. Compare counts: SYNCs sent, camera pulses, flash counter 0x210A, reported
  frames. Stop mid-line.
- **Acceptance:** flash offset D ± p99 jitter ≤ 100 µs. All four counts equal. After a stop
  the motor halts, the LED is off, and completion reports `aborted: 1`.
- **Optional:** on a standalone board the LOCAL route drives LaserStrobe directly without
  CAN. Verify only if such a board is in use.

### WP6 — UC2-REST wrappers

**Depends:** WP5 contract. **Goal:** typed Python calls for ImSwitch.

- **Automated:** unittest with the mock parent: payload keys and units, µm to steps,
  report and completion callbacks, register and unregister.
- **Bench:** a Python script runs one line against the HAT and receives every report.

### WP7 — HIK trigger path in ImSwitch

**Depends:** WP0. Runs in parallel with WP1–WP6. **Goal:** every trigger yields one frame
with its trigger index.

- **Automated:** unit tests with a fake MvCamera: activation and delay are set, shutter mode
  is set when the feature exists and skipped otherwise, `nTriggerIndex` reaches `getChunk`.
- **Hardware:** 1 000 triggers at 30 Hz from the existing stage scan trigger.
- **Acceptance:** 1 000 frames with consecutive trigger indices, no drops. Record the
  maximum trigger rate at the chosen window and ROI.

### WP8 — StageMap strobe mode

**Depends:** WP6, WP7. **Goal:** the prescan uses strobed sweeps when available.

- **Automated:** unit tests of pure functions. Pair frames to reports by trigger index,
  with gaps and a start offset. Placement at `x + v·D` for both sweep directions. The
  delay-calibration metric picks the right D on synthetic frames. A simulation end-to-end
  test through the API with the virtual microscope produces a strip.
- **Behaviour:** capability check on the firmware version, fallback to today's free-running
  prescan, LED off on stop and on error.

### WP9 — Hardware acceptance

**Depends:** WP8. **Goal:** the targets in the design doc, on the real instrument.

- **Test:** sweep a USAF or grid slide at 10, 30 and 50 mm/s.
- **Acceptance:** edge width versus a static image ≤ 1 px. Seam error between neighbouring
  frames ≤ 2 px. Zero dropped frames at the target rate. A frame with strobe disabled has
  a mean below 1 % of a lit frame. LED off after stop, error and power cycle.
- **Wrap-up:** update both docs with measured numbers.

## 4. Sequencing

```
WP0 ─┬─ WP1 ── WP2 ─┬─ WP3 ─┐
     │              └─ WP4 ─┴─ WP5 ── WP6 ─┐
     └─ WP7 ───────────────────────────────┴─ WP8 ── WP9
```

WP0 is the only hard gate. WP2 is the second decision point: if its p99 latency exceeds
100 µs even after pinning the CAN task to one core, the camera window must grow by the
measured jitter, which costs frame rate but not correctness.

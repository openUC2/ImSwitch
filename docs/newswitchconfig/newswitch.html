01

The big picture

newswitch is a FastAPI app whose entire functional surface is managed by a rekuest-next agent embedded in the server. Nothing in the backend defines REST endpoints for microscope features by hand. Instead:

  • functions decorated with @register become remotely callable actions;
  • data classes decorated with @state become reactive shared state, pushed to every browser as JSON-patches;
  • service classes marked with @context (the “managers”) are dependency-injected into those functions by type annotation;
  • the frontend generates typed React hooks from the running backend’s schema endpoints, so UI code never hand-writes API calls.
Companion

An interactive walkthrough of the same material — four lifecycles as clickable swimlanes — exists as the newswitch runtime explorer artifact. This document is the reference; that one is the map.

02

rekuest concepts, one by one

Agent and actors (the docstring, decoded)

rekuest uses the classic distributed actor model. Translated to newswitch:

The Agent (FastApiAgent, created by configure_fastapi in create_app) is the runtime container for the whole app. It does not do microscope work itself. It owns:

  • contexts — the live manager instances (everything @context);
  • states — the live state instances (everything @state), each with a revision counter and a serialized (“shrunk”) copy;
  • locks — named task locks such as stage_position;
  • the implementation map — one entry per @registered function;
  • the collected @startup hooks and @background workers;
  • all running assignments (tasks) and the actors executing them;
  • a SQLite sink/retriever (agent_data.db) recording task history — what the frontend /replay page reads.

An actor is the execution vehicle for one implementation. When a client assigns a task (“run move_stage with these args”), the agent routes the assignment to that implementation’s actor, which runs the function — sync functions in a worker thread via koil, async ones on the loop — and reports lifecycle events back: STARTED, PROGRESS, YIELD, PAUSED, CANCELLED, COMPLETED, FAILED.

Guardian vs non-guardian actors: actors the agent spawns directly (one per registered implementation) are “guardian” actors; an actor may itself call other actions (acall inside a function body), spawning subordinate actors whose lifetime it owns. That is the “hierarchical structure” the docstring describes. In newswitch you mostly interact with the first level.

Why it looks different from Arkitekt

In upstream Arkitekt the agent connects out to an arkitekt server and receives assignments from there. In newswitch the FastAPI contrib replaces that transport: the agent lives inside uvicorn and browsers talk to it directly over /ws plus a few REST routes. Same model, no external server.

AppContext and @app_context

rekuest_next.agents.base.AppContext is nothing more than a marker protocol — a class with one attribute, __rekuest_app_context__. The @app_context decorator stamps that attribute onto your class. That is all; no behaviour.

Its purpose: the object you pass as app_context= into configure_fastapi (newswitch passes ImswitchConfig) travels into agent.aprovide(context=…) and becomes injectable by type into hooks and registered functions. That is why provide_managers(app_context: ImswitchConfig) receives the config: the parameter’s type annotation is matched against the app-context class. Think of it as the DI slot reserved for “the configuration of this deployment”.

@startup — the composition root

@startup
async def provide_managers(app_context: ImswitchConfig) -> Tuple[
    FrameBroadcaster, UC2BusManager, UC2State, StageManager, …, StageState, …
]:

Startup hooks run once, when the agent boots (inside aprovide, before anything is callable). Two pieces of magic, both driven purely by type annotations:

  1. Parameter inspection — the “app-context, state, and context dependencies”: each parameter is matched by its annotated type against (a) the app-context class, (b) already-published @state classes, (c) already-published @context classes. Matching objects are injected.
  2. Return annotation → publication — the Tuple[…] return annotation tells the agent what each returned object is. Objects whose class or protocol is @context go into agent.contexts; objects whose class is @state go into agent.states (serialized, revision 0, immediately subscribable).

So provide_managers is the composition root: everything it returns is published for the rest of the agent lifecycle and becomes injectable into every @register/@background function.

Footgun

If you build a new manager and forget to add it to both the returned value and the return annotation, injection fails at call time with StateRequirementsNotMet.

Context dependency means “give me the live manager instance of this type” (e.g. stage: StageManager). State dependency means “give me the live shared state instance” (e.g. state: StageState). Contexts are never serialized; states are.

@register — actions

Any function becomes a remotely callable action:

@register(locks=["stage_position"], optimistics=[…])
def move_stage(stage: StageManager, x: float | None = None, …) -> None: …
  • Parameters that are contexts or states are injected and stay invisible to callers; everything else becomes the action’s argument schema (its “ports”), which is what the frontend codegen turns into a zod schema.
  • locks=[…] serializes conflicting actions and surfaces “locked” to the UI.
  • optimistics=[…] describes how the UI should predict the state change before the backend confirms it — instant slider and position feedback.
  • Inside the body, progress(pct, msg) and pausepoint() power the live progress bar and the pause/step buttons.
  • Registration happens at import time into the default app registry — which is why app.py imports newswitch.registers.uc2 and the routines purely for their side effects.

@background — daemons

@background functions are long-running workers started right after the startup hooks; async ones run on the event loop, sync ones in a dedicated thread. They use the same injection: run_uc2_bus(uc2_bus: UC2BusManager) gets the live bus. newswitch runs three — the detector acquisition loop, the UC2 bus connection pump, and the UC2 event → state dispatcher.

The four class decorators

DecoratorFromWhat it does
@context rekuest_next.agents.context Marks a class (usually a Protocol) as an injectable service — a “manager”. Optionally declares locks=[…] shared by all its users. Stores only marker attributes; no wrapping.
@state rekuest_next.state.decorator The heavy one. Introspects the class into a state schema (a port per field), registers it, and rewrites the class so instances are evented: every setattr (1) checks that required_locks are held, (2) applies the change, (3) publishes a JSON-patch with a new revision to all subscribers.
@model rekuest_next Marks a dataclass as a serializable data structure so it can appear inside action arguments, returns and state fields. Used for config and value objects (StageConfig, Illumination, UC2CanBusConfig). No reactivity.
@runtime_checkable stdlib typing Not rekuest at all. Allows structural isinstance(obj, SomeProtocol) checks, which the tests use (isinstance(bus, UC2BusManager)).

The app registry and bloks

get_default_app_registry() returns the global AppRegistry — the accumulator for everything above: implementations, state schemas, locks, bloks. @register writes into it implicitly; registry.register(fn) is the explicit spelling used for the routines:

default_app_registry.register(acquire_multidimensional_acquisition)
default_app_registry.register(scan_region)

You can register any function whose non-injected parameters are serializable types — that is how a new “app” (in the ImSwitch sense) gets its backend surface.

register_blok(name, jsx(…)) is different: it ships a server-defined UI fragment — a JSX-like DSL parsed on the backend, sent to the frontend via the schema endpoints, and rendered there. Bloks can bind to states (@self.ObjectiveState.mounted_lenses), loop (<foreach>) and invoke actions (onClick="@self.switch_objective(lens.slot)"). Use them for small panels that should not require a frontend build.

What is “jonda”?

Simply the arbitrary name of a demo blok left in app.py — the card itself reads “Bene don’t look at this yet, this is just a placeholder.” It demonstrates the binding syntax and can be renamed or removed freely.

Boot lifecycle, step by step

What happens when you run uvicorn main:app --port 8099:

  1. 01
    Import time

    Importing newswitch.app executes every @register, @state, @context, @startup and @background decorator — the default app registry fills up. main.load_config() optionally reads NEWSWITCH_CONFIG, then create_app(config) runs.

    backend/main.py · backend/newswitch/app.py
  2. 02
    create_app builds the FastAPI app

    Adds CORS, then calls configure_fastapi(app, default_app_registry, app_context=config, …).

    newswitch/app.py → create_app()
  3. 03
    The agent is constructed

    configure_fastapi builds the FastApiAgent from the registry, wiring a SQLite sink and retriever for task history.

    rekuest_next/contrib/fastapi/routes.py:177
  4. 04
    Core routes mounted immediately

    add_agent_routes(…) mounts the single multiplexed websocket /ws — carrying task events, state patches and lock events — plus /assign, /cancel, /pause, /resume, /step.

    rekuest_next/contrib/fastapi/routes.py:75
  5. 05
    Lifespan installed

    app.router.lifespan_context = lifespan replaces FastAPI’s own startup/shutdown context manager, so agent boot rides the web server’s lifecycle. A lifespan is an async context manager: everything before yield is startup, after it is shutdown.

    rekuest_next/contrib/fastapi/routes.py:254
  6. 06
    Server start → lifespan enters

    The deferred route groups mount: /tasks, /states, /locks, per-implementation execution routes, and the three schema endpoints the frontend codegen reads — /schemas/implementations, /schemas/states, /schemas/locks. OpenAPI is configured and app.state.agent is set.

    rekuest_next/contrib/fastapi/routes.py:212
  7. 07
    agent.aprovide(context=config) is spawned

    Inside async with agent: the provide task starts and orchestrates the rest of the boot. On shutdown this task is cancelled, tearing everything down — which is why abackground() implementations must re-raise CancelledError.

    rekuest_next/contrib/fastapi/routes.py:236
  8. 08
    @startup provide_managers runs

    ImswitchConfig is injected by type. The body builds every state and manager, choosing VirtualUC2Bus, UC2CanBus or UC2RestBus from config.uc2_transport, and returns one big tuple.

    newswitch/app.py → provide_managers()
  9. 09
    Publication

    Each returned object is filed by its annotated type: contexts become live service objects, states are serialized at revision 0 and become subscribable. From this moment any @register function can ask for StageManager or StageState by annotation.

  10. 10
    @background workers start

    run_detector_loop (frames → FrameBroadcaster), run_uc2_bus (connects the transport, pumps telemetry, reconnects with exponential backoff) and run_uc2_event_dispatch (mirrors bus events into StageState/UC2State).

    rekuest_next/agents/base.py → arun_background()
  11. 11
    Frontend connects

    At build time the Vite plugin already fetched /schemas/* and generated typed hooks. At runtime the browser opens /ws, checks out current state snapshots with their revisions, and subscribes to patches, task events and locks.

    frontend/plugins/generate-app.ts · frontend/src/lib/rekuest/transport/
04

Request lifecycle — what a button press does

  1. A component calls a generated hook: useMoveStage().call({x: 100}).
  2. The transport POSTs to /assign with the implementation name and args; the args were validated client-side against the generated zod schema.
  3. The agent checks the action’s locks, records the assignment, and hands it to the actor; the function body runs with its contexts and states injected.
  4. Lifecycle events stream to every subscribed client over /ws; the UI’s ProgressDisplay and lock indicators react.
  5. Any @state mutation during the call — for example the UC2 dispatcher writing StageState.x — is JSON-patched over the same socket.
  6. Cancel, pause and step buttons hit /cancel, /pause, /step. pausepoint() in the body is where pauses take effect; cancellation raises CancelledError inside the body, which the UC2 bus turns into a hardware stop command.
  7. Terminal events and results are persisted to SQLite, feeding /replay.
05

State flow and optimistic updates

  • A @state instance is a normal Python object — mutating an attribute is the entire API (stage_state.x = 42.0). The evented subclass publishes {op: replace, path: /x, value: 42.0, rev: n} to the agent, which fans it out to /ws subscribers; each frontend zustand store applies patches in revision order.
  • Writes require the state’s required_locks to be held: either you are inside an action that declared the lock, or you wrap the write in with acquired_locks("stage_position"): — what the UC2 event dispatcher does.
  • optimistics=[OptimisticInput(state=…, path=…, accessor=…)] on @register lets the UI apply a predicted patch immediately when the call is made; the real patch reconciles it.
06

Video streaming (separate from /ws)

Bulk pixels never travel through the state system. The detector background loop pushes frames into the FrameBroadcaster, which owns shared encoders (zstd, H.264) keyed by (slot, config) — ten browsers cost one encode. Browsers open WS /stream/zstd/{slot} or /stream/h264/{slot} and decode with fzstd / jmuxer. Scan and acquisition code can broadcast into additional slots, for example stitched-map tiles.

08

The UC2 hardware layer

protocols/uc2.py defines the transport-agnostic UC2BusManager: stage verbs in micrometers, laser and LED in raw PWM, galvo in DAC counts, objective slots and node scan — plus subscribe() yielding typed events (PositionUpdate, MotionDone, HomingChanged, EStopChanged, ButtonPressed, NodeSeen, BusError).

Three interchangeable implementations, selected in provide_managers from uc2_transport: UC2CanBus (CANopen via uc2canopen.aio — node map, µm↔steps scaling, event-driven motion-done from TPDO frames), UC2RestBus (serial JSON via uc2rest.aio — single ESP32 master, pattern-keyed firmware events) and VirtualUC2Bus (simulator). Both real buses reconnect with exponential backoff and surface failures as BusError plus UC2State.last_error.

Two background workers keep it alive: run_uc2_bus owns the connection and event pump; run_uc2_event_dispatch consumes subscribe() and mirrors telemetry into StageState and UC2State under the stage_position lock — the “spontaneous events” path. Device managers such as UC2StageManager only ever call bus verbs, never a concrete transport.

09

What is the Expanse?

The Expanse is newswitch’s infinite sample-space canvas — the world map of everything that has been imaged. ExpanseState holds placed Images, each with its stage-space affine transform; position, pixel size and orientation come from the MetadataManager and the Kube optics model. ExpanseManager adds and clears entries; acquisitions push their frames into it. The frontend renders it as the three.js scene in frontend/src/components/stage/ — planes textured from zarr tiles, with camera navigation. clear_expanse is the registered action that empties it.

Conceptually it replaces ImSwitch’s StageMap: a persistent, transform-correct mosaic of acquired fields of view.

Known wart

The module docstring in protocols/expanse.py still reads “Stage Manager Protocol” — a copy-paste leftover, worth fixing.

10

Frontend in one paragraph

frontend/plugins/generate-app.ts — a Vite plugin run on every dev and build — fetches /schemas/implementations|states|locks from the running backend and emits src/apps/default/hooks/{actions,states,locks}/*.ts: zod schemas plus typed hooks such as useMoveStage and useStageState. These files are committed, and just drift-check fails CI if they diverge from the backend. The hand-written runtime in src/lib/rekuest/ manages the /ws connection, task assignment, patch application and locks. Components in src/components/microscope/ consume only the generated hooks.

Workflow

If you add or rename a backend action or state: run the backend, then cd frontend && yarn build, and commit the regenerated files.
